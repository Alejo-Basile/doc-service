## Bugs encontrados y corregidos

1. **Envelope de la cola inconsistente con SPEC §5.4** — `doc-service` publicaba sólo el campo
   `payload`; el `core` de `extraction-worker` usa `#[serde(deny_unknown_fields)]` y espera campos
   planos. Contrato a alinear: issue **#34**. (Track E, review entre repos.)
2. **Webhook: `UPLOADED` transitorio encolaba objetos inválidos** — el orden
   `PENDING_UPLOAD → UPLOADED → validar → REJECTED` disparaba el Change Stream/relay con un
   `UPLOADED` que nunca fue un PDF (detectado en E2E-01 local con un `.txt` renombrado:
   el documento terminaba `REJECTED` pero igual se encolaba). Corrección: validar `%PDF-`
   **antes** de promocionar (`PENDING_UPLOAD → REJECTED` directo). **PR #35**.
3. **`resume token` inválido tras reinicio de entorno** — al reusar una base con un token
   apuntando a un oplog descartado, `getMore` falla con `ChangeStreamFatalError`. El watcher lo
   detecta, borra el token y reabre el stream fresco (auto-sana). Cubierto por
   `TestWatcher_RecuperaTrasTokenInvalido`; observado en el E2E (`resume token invalidado: stream
   reiniciado fresco`).
4. **Driver Mongo v2 (csot) mataba el watcher a los 30 s** — `ClientOptions.Timeout` aplica a toda
   operación, incluido `getMore`; se le dio al watcher un cliente propio con `Timeout=0`.
   `TestWatcher_ClienteSinTimeout_SuperaVentanaDeOperacion`.

## Evidencia E2E-01 (local: Mongo RS + Redis + MinIO reales)

Contrato asíncrono: `POST /api/v2/documents` → upload prefirmada → webhook →
`UPLOADED` → mensaje en `stream:pdf-processing`.

| Escenario | Resultado |
|---|---|
| PDF válido (`%PDF-…`) | upload `204`; webhook `ok`; estado `UPLOADED`; **1** mensaje encolado |
| `.txt` renombrado (`application/pdf`) | webhook `rejected`; estado `REJECTED`; **0** mensajes encolados (tras PR #35) |
| Subida de 26 MB (límite 25 MB) | `400 EntityTooLarge` de MinIO (policy `content-length-range`) |

```bash
# verificación de la cola
docker exec redis_e2e redis-cli -a "$REDIS_PASSWORD" XLEN stream:pdf-processing
docker exec redis_e2e redis-cli -a "$REDIS_PASSWORD" XRANGE stream:pdf-processing - +
```
